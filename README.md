# Prompt Manager

Python 콘솔에서 다양한 프롬프트를 등록하고 관리할 수 있는 프로그램입니다.

프롬프트를 추가하고 목록, 카테고리별 조회, 검색, 상세 보기, 즐겨찾기 등의 기능을 사용할 수 있습니다.

## 개발 환경

- Python 3.10 이상
- Visual Studio Code
- Git
- GitHub

## 주요 기능

1. 프롬프트 추가
2. 프롬프트 목록 보기
3. 카테고리별 조회
4. 프롬프트 검색
5. 프롬프트 상세 보기
6. 즐겨찾기 추가 및 해제
7. 즐겨찾기 목록 보기
8. 프로그램 종료

- 기타

## while 반복문 사용 이유와 종료 조건

프로그램의 메인 메뉴는 사용자가 여러 기능을 반복해서 사용할 수 있도록 `while True` 반복문을 사용했습니다.

메뉴에서 하나의 기능을 실행한 후에도 프로그램이 종료되지 않고 다시 메뉴를 보여주어야 하기 때문에 반복문을 사용했습니다.

메인 반복문은 사용자가 메뉴에서 `0. 종료`를 선택하면 종료됩니다.

```python
while True:
    show_menu()

    choice = input("메뉴 번호를 선택하세요: ")

    if choice == "0":
        print("프로그램을 종료합니다.")
        break

반복문의 역할
프로그램이 실행되는 동안 계속해서 메인 메뉴를 보여줍니다.
사용자가 기능을 선택하면 해당 기능을 실행합니다.
기능 실행이 끝나면 다시 메인 메뉴로 돌아옵니다.
잘못된 메뉴 번호를 입력해도 프로그램을 종료하지 않고 다시 메뉴를 보여줍니다.
종료 조건

사용자가 메뉴에서 0을 입력하면 if choice == "0" 조건이 실행됩니다.

이때 break를 사용하여 while True 반복문을 종료하고 프로그램을 종료합니다.

또한 프롬프트 추가 기능에서는 제목, 내용, 카테고리의 올바른 입력이 이루어질 때까지 while 반복문을 사용하여 입력을 다시 요청하도록 구현했습니다.

### 리스트의 장점
- 여러 개의 프롬프트를 하나의 자료구조로 관리하기 쉽습니다.
- 반복문을 사용하여 전체 프롬프트를 쉽게 조회할 수 있습니다.
- 새로운 프롬프트를 `append()`를 사용하여 쉽게 추가할 수 있습니다.

### 리스트의 단점
- 특정 데이터를 찾기 위해 반복문을 사용해야 할 수 있습니다.
- 인덱스로 접근하기 때문에 데이터의 의미를 바로 알기 어렵습니다.

### 딕셔너리의 장점
- `title`, `content`, `category`, `favorite`와 같이 키를 사용하여 데이터를 명확하게 관리할 수 있습니다.
- 필요한 데이터를 키 이름으로 쉽게 가져올 수 있습니다.
- 하나의 프롬프트와 관련된 여러 정보를 묶어서 관리하기 좋습니다.

### 딕셔너리의 단점
- 키 이름을 일관되게 관리해야 합니다.
- 데이터 항목이 많아지면 구조가 복잡해질 수 있습니다.

### 이 프로그램에서 리스트와 딕셔너리를 함께 사용한 이유

여러 개의 프롬프트를 저장해야 하므로 전체 프롬프트는 리스트로 관리했습니다.

각 프롬프트는 제목, 내용, 카테고리, 즐겨찾기 여부 등 여러 정보를 가지고 있기 때문에 하나의 프롬프트는 딕셔너리로 관리했습니다.

따라서 다음과 같은 구조로 데이터를 저장했습니다.

```text
리스트
 ├── 딕셔너리 → 프롬프트 1
 ├── 딕셔너리 → 프롬프트 2
 └── 딕셔너리 → 프롬프트 3

```bash
python prompt_manager.py

## 브랜치 분리 기준과 병합 시점

이 프로젝트에서는 기능을 개발할 때 `main` 브랜치의 안정적인 상태를 유지하기 위해 기능별로 별도의 브랜치를 생성했습니다.

### 브랜치 분리 기준

새로운 기능을 독립적으로 개발할 필요가 있을 때 `main` 브랜치에서 기능 브랜치를 생성했습니다.

프롬프트 목록 기능을 개발할 때 다음과 같이 `feature/prompt-list` 브랜치를 생성했습니다.

```bash
git checkout -b feature/prompt-list

feature/prompt-list 브랜치에서는 프롬프트 목록 조회 기능을 개발하고 테스트했습니다.

병합 시점

프롬프트 목록 기능의 구현과 테스트가 완료된 후 해당 기능을 main 브랜치에 병합했습니다.

먼저 main 브랜치로 이동했습니다.

git checkout main

그 다음 기능 브랜치를 main에 병합했습니다.
git merge feature/prompt-list
기능 개발과 테스트가 완료된 후 병합함으로써 main 브랜치에는 완성된 기능만 반영되도록 했습니다.

브랜치 작업 흐름

main
 │
 ├── feature/prompt-list
 │       │
 │       └── 프롬프트 목록 기능 개발 및 테스트
 │
 └── main ← feature/prompt-list 병합

이와 같이 기능별로 브랜치를 분리하면 기능 개발 중 발생한 문제가 main 브랜치에 바로 영향을 주는 것을 줄일 수 있고, 기능이 완성된 후 안정적으로 병합할 수 있습니다.

## 중복 제목 처리 규칙

이 프로그램에서는 프롬프트 제목의 중복을 허용합니다.

같은 제목의 프롬프트라도 내용이나 카테고리가 다를 수 있기 때문에 제목만으로 중복 여부를 판단하여 등록을 막지 않습니다.

따라서 동일한 제목을 가진 프롬프트를 추가할 경우에도 각각 별도의 프롬프트로 리스트에 저장됩니다.

## 병합 충돌 발생 원인 및 해결 절차

Git에서 서로 다른 브랜치에서 같은 파일의 같은 부분을 수정한 경우 병합 충돌(Merge Conflict)이 발생할 수 있습니다.

### 병합 충돌 발생 원인

`main` 브랜치와 기능 브랜치에서 동일한 파일의 같은 부분을 서로 다르게 수정한 경우 Git이 어떤 내용을 선택해야 할지 판단할 수 없어 충돌이 발생합니다.

### 병합 충돌 해결 절차

1. `git merge` 실행 후 충돌이 발생하면 Git이 충돌이 발생한 파일을 알려줍니다.
2. 충돌이 발생한 파일을 VSCode에서 열어 충돌 표시를 확인합니다.
3. `<<<<<<<`, `=======`, `>>>>>>>` 표시를 확인하고 최종적으로 사용할 내용을 선택합니다.
4. 충돌 표시를 모두 제거하고 파일을 저장합니다.
5. 다음 명령어로 해결된 파일을 Staging 영역에 추가합니다.

```bash
git add 파일명

## 카테고리 변경 방법

프로그램에서 사용하는 카테고리를 추가하거나 변경하려면 `add_prompt()` 함수와 `show_category()` 함수 내부의 `categories` 리스트를 수정해야 합니다.

현재 카테고리는 다음과 같습니다.

- 텍스트 생성
- 이미지 생성
- 영상 생성
- 페르소나
- 자동화
- 기타

새로운 카테고리를 추가할 경우 `add_prompt()` 함수와 `show_category()` 함수의 `categories` 리스트에 동일하게 추가해야 합니다.

두 함수의 카테고리 목록을 동일하게 유지해야 프롬프트 추가 기능과 카테고리별 조회 기능에서 같은 카테고리를 사용할 수 있습니다.
